# eMudhra 開発環境診断 1.0 — 詳細ガイド

このPCの開発ツールを調べ、eMudhra証明書問題について、確認できた範囲と次に必要な行動を表示します。バージョン照合の基準日は **2026-11-02** です。参照データは固定スナップショットで、自動更新しません。個別の基準日と出典は結果の「検査データ」で確認できます。

## 対応環境と導入

| OS | CPU別の配布対象 | 配布形式 | 起動ファイル |
|---|---|---|---|
| Windows | x64 / arm64 | zip | `診断を開始.cmd` |
| macOS | Intel（x64）/ Apple Silicon（arm64）| tar.gz | `診断を開始.command` |
| Linux | x64 / arm64 | tar.gz | `診断を開始.sh` |

これはビルドが用意されている対象の一覧です。全対象での実行確認を意味しません。最小OSバージョンは確定していません。Linux用ランタイムはGNU/Linux向けで、muslベースの環境での動作は確認していません。[実行確認済みの範囲と未検証事項](VALIDATION-ja.md)をご覧ください。

配布版はOS・CPUが合う圧縮ファイルを選び、書き込み可能な場所へすべて展開します。`app`・`docs` を移動・削除せず、起動ファイルを実行してください。同梱Pythonを使うため、別途Pythonを導入する必要はありません。Linuxではファイル管理アプリの「実行」や「端末で実行」を選ぶ場合があります。

ソース版には同梱Pythonと配布用の起動ファイルはありません。Python 3.8以上を用意し、次の節のコマンドを使います。Pythonは診断処理を制御するためのもので、対象のPython・Node.js・Javaなどの通信を代用しません。診断対象のソフトや不足ライブラリを自動インストールすることもありません。

## 実行する

配布版の通常操作は[かんたん操作ガイド](START-HERE-ja.md)、追加オプションは配布物の `docs/使い方.html` にあります。

ソース版は、このフォルダーでターミナルを開いて実行します。

```bash
# macOS / Linux
python3 -B audit.py --out ./report
# 外部へ接続せず、版と設定を確認する
python3 -B audit.py --offline --out ./report-offline
# 検査する種類を絞る
python3 -B audit.py --only python,node,java --out ./report-selected
# オプション一覧を確認する（診断は行わない）
python3 -B audit.py --help
```

```powershell
# Windows PowerShell（Python Launcherを導入している場合）
py -3 -B audit.py --out ./report
py -3 -B audit.py --offline --out ./report-offline
```

Windowsで `py` がない場合は、Python 3.8以上を起動する `python` または実行ファイルのフルパスを使います。フルパスはPowerShellで `& 'C:\path\to\python.exe' -B audit.py --out ./report` の形式で指定できます。ソース版の `run-checks.cmd` は同梱ランタイム専用なので使用しません。

通常は数分程度ですが、ツール数・接続状況によって長くなります。CLIでは終了後に表示される保存先の `report.html` を手動で開きます。配布版の「診断を開始」は結果画面を自動で開き、配布フォルダーの `結果/日時/` に保存します。CLIで `--out` を省略すると、現在のフォルダーの `emudhra-report-日時/` に保存します。同じ `--out` を再利用すると、既存の結果を上書きします。

通常の検査中はCtrl+Cで中断し、取得済みの結果を保存できます。初期化や保存処理中の中断などでは結果を作れない場合があります。中断した診断を完了済みとは扱わないでください。

## 結果を読む

| ファイル | 用途 |
|---|---|
| `report.html` | ブラウザで開く結果画面。ツール → 導入先の順に確認する |
| `summary.txt` | テキストで確認する要約 |
| `report.json` | 個別の検査データと判定根拠。連携・詳細確認向け |

結果フォルダーには表示用のCSS・JavaScriptも作られます。別の場所へ移す場合はフォルダー全体をコピーしてください。

まず「次の行動」を確認し、「版の判定」「通信の検証」「不足情報と次の確認」を開きます。根拠は「検査データ・原記録」や各軸の「記録」リンクで確認できます。

| 表示 | 意味と確認すること |
|---|---|
| 更新が必要 | 適用できる版の根拠から更新対象と判定。表示された導入先・本体・部品を確認して更新する |
| 設定の修正が必要 | 証明書検証の無効化など、具体的な設定上の問題を検出。表示された設定を確認する |
| 追加確認が必要 | 通信未検査、取得・実行失敗、独自配布など。理由と次の確認を読む |
| 検査した範囲で問題なし | 表示された導入先・接続先で拒否を確認し、記録上の未確認事項がない。全体の安全保証ではない |
| 問題の証明書を受け入れた・対応が必要 | 実測等で問題を検出。版が良好でも対応が必要 |
| 検出した問題への対応が必要 | 問題の根拠を版・設定・通信へ限定できない。記録された理由と手順を確認する |
| 見つからなかった対象 | 今回の探索先で未発見。未インストールの確定ではない |
| 対象外・環境情報 | OSに非該当の対象や配置情報。問題なしとは別扱い |

主分類は1ツール1件です。更新と設定修正などが併存する場合は両方の行動フィルターに含まれるため、フィルター件数の合計は重複します。同じツールの別導入先や別venvは分けて確認してください。

本体が最新版でも、同梱Electron・Go・JREなどが対策版未満の場合があります。結果の同梱バージョンと対策版を比較し、配布元の対応版、提供予定、独自修正の有無を確認してください。部品だけを手作業で差し替える案内ではありません。版の条件を満たしても、未検査の通信や別経路の確認は残ります。

通常サイトにつながること、CAファイルに対象証明書がないこと、版が対策基準を満たすことは、問題の証明書を通信で拒否した証拠とは別です。期限・名前不一致・DNS・タイムアウト・汎用エラーだけでは信頼拒否と判定しません。HTTPSが成立しても証明書経路を確認できない場合は、プロキシ介在などを考慮して追加確認とします。詳しくは[判定軸と件数の読み方](ACTION-PRESENTATION-ja.md)をご覧ください。

## 必要な対象だけ追加する

既定ではこのPCの開発環境を検査します。任意のプロジェクト、全ディスク、別ユーザーの環境を網羅するものではありません。以下はmacOS / Linuxのソース版の例です。Windowsでは `python3` を `py -3` 等に読み替え、実際のパスを指定してください。

```bash
# 指定プロジェクトのGit・npm設定、Cargo.lock、直下のvenvなども確認
python3 -B audit.py --project /path/to/project --out ./report-project
# 指定したPython環境を追加
python3 -B audit.py --python /path/to/project/.venv/bin/python --out ./report-venv
# 指定ディレクトリ内のvenvを探索（最大100環境）
python3 -B audit.py --scan-venvs /path/to/projects --only python --out ./report-venvs
# 指定したアプリを追加
python3 -B audit.py --only apps --app /path/to/application --out ./report-app
# パッケージ管理・対応CLIの固有通信を確認
python3 -B audit.py --only packages --out ./report-packages
# 指定した稼働中Linuxコンテナも確認
python3 -B audit.py --container container-name --out ./report-container
```

Windowsのvenvは `Scripts\python.exe` を指定します。`--python`・`--node`・`--java`・`--curl`・`--git`・`--wget`・`--httpie`、追加言語の各オプションは実行ファイルの追加指定に使えます。空白を含むパスは引用符で囲んでください。

`--container` は現在のDocker contextに接続し、指定した稼働中のLinuxコンテナへ `docker exec` を実行します。イメージ取得、コンテナの作成・再起動はしません。`--offline` との併用は不可で、`--only` を指定する場合は `docker` を含める必要があります。コンテナ内のTLSとDocker Engine・BuildKitのregistry接続は別の対象です。WSLや仮想マシンは、それぞれの環境内で実行してください。

macOSでは `--browser-results` で、通常ブラウザのUIから収集した観測JSONを取り込めます。Windows/Linuxでは未対応です。入力JSONには `schema_version: 1`、`browser`（Chrome/Edge/Safari/Firefox）、`version`、`profile`、タイムゾーン付きの `observed_at`、`source: "native-ui"`、`security_bypassed: false` と `samples` が必要です。通常サイトと代表4接続先それぞれの `url`・`result`・画面上の根拠 `observation` を記録します。未来時刻ではない24時間以内の観測で、現在の導入版に一致するものだけを扱います。警告の回避や証明書検証の無効化をした観測は取り込めません。`loaded` だけでは問題の証明書を受け入れた証拠にならず、観測した `certificate_chain_sha256` に参照対象のTLS証明書指紋がある場合に限り受入れと扱います。`--only` を指定する場合は `browser` を含めてください。

## 検査の範囲と注意点

PATH、OSごとの既知の配置、Homebrew・Scoop・pyenv・Conda・nvm・mise・asdfなどの既知の管理先、Windowsのアプリ登録情報を限定的に探索します。任意のアプリやプロジェクトを無制限に再帰探索しません。探索・解析の上限、読取失敗、未対応形式は検査データに残します。

対応するクライアントでは、通常サイトと4つの代表検証先へHTTPS接続します。主な対象はPython、Node.js、Java、Go、Ruby、PHP、.NET、PowerShell、curl、Gitなどです。コンパイラ・SDK・ライブラリが必要な検査もあり、条件が不足する場合は見送ります。GUIアプリの同梱部品やCAバンドルを静的に確認できても、そのアプリ自体の通信を確認したとは扱いません。

一部のパッケージ管理ツール・CLIは、認証情報や実プロジェクトを使わず、合成データと一時設定で通信を試します。OSV-Scannerでは合成依存だけを公式APIへ照会し、利用者のプロジェクトの脆弱性スキャンは行いません。wget・HTTPieなどは診断時の認証送信を抑えるため、普段のツール設定を使わない場合があります。プロキシ・CA設定の継承や見送り条件はツールごとに異なります。普段の設定、認証付きの取得先、リダイレクト後の経路を確認済みとは扱わないでください。

Safe Chainは本体版と連携候補を確認します。macOS ARM64の特定の公式版で隔離条件が成立する場合だけ、一時コピーと合成localhostによるTLS検査を行います。これはeMudhra公開検査先や普段の通信の確認ではありません。認証付きプロキシやSafe Chainの保護を迂回する可能性がある場合は、対応する固有通信を見送ります。個別条件・未検査範囲は[P2-COVERAGE-ja.md](P2-COVERAGE-ja.md)に記載しています。

- 診断は導入済みの対象コマンドを実行し、レポートと一時ファイルを作成します。信頼できる環境で実行してください。
- 対象ソフトの更新・設定変更・証明書ストア変更・パッケージ導入は行いません。管理者権限は不要です。
- 通常は外部へのHTTPS接続を行います。組織のネットワーク利用ルールを確認してください。外部通信を省く場合は `--offline` を使いますが、通信の安全性は未確認のままです。
- SSH/SFTPはTLSの検査結果に含めません。HTTPS/FTPS等の確認とも区別します。
- レポートにはローカルパスや環境情報が含まれます。共有前に確認してください。

## 起動・表示に困ったとき

配布版は圧縮ファイルの中から直接実行せず、すべて展開してください。結果を書き込めない場合は、書き込み可能な場所へ展開し直します。OS・CPUの実行形式エラーは配布対象を確認してください。OSの実行制限が表示された場合は、メッセージと配布元の情報をIT担当へ伝え、セキュリティ設定を無効化せずに確認します。

結果画面だけが開かない場合は、表示された保存先の `report.html` を手動で開いてください。Linuxの自動表示には `xdg-open` とブラウザを利用できる環境が必要です。画面のない環境ではCLIを使い、保存した結果を閲覧できる環境へフォルダーごとコピーします。

CLIの終了コードは `1` が具体的な対応あり、`2` が追加確認・未検査あり、`0` がそのどちらもない場合です。引数エラーでも `2` を返すため、結果ファイルと標準エラーを確認してください。「診断を開始」の終了コードは別で、結果画面を開ければ診断内容にかかわらず `0`、起動・保存・表示に失敗すると `3` です。いずれも探索範囲外の安全性を保証しません。
